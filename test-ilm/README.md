# Test ILM - Local stack

This development-only Docker Compose stack runs Core, the administrator UI,
Auth, OPA policies, Scheduler, RabbitMQ, PostgreSQL, Keycloak, and Kong. The
gateway publishes only on `127.0.0.1:8000`.

From the repository root, prepare the generated realm and queue definitions:

```powershell
.\test-ilm\prepare.ps1
```

Then start the stack from this directory:

```powershell
Set-Location .\test-ilm
docker compose --env-file .\.env -f .\compose.yaml up -d
```

Open <http://localhost:8000/administrator/>. The development user and
generated passwords are in `.env`; do not share or commit that file. Keycloak
administration is available at <http://localhost:8000/kc/admin/>.

## Environment file

`.env-template` lists every property required by the local stack. Copy it to
`.env`, replace each value in braces with the described value, and keep `.env`
private; it is ignored by Git. The defaults shown in the descriptions match
those generated by `prepare.py`. Generate a different random value for every
password and secret, for example:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Run the command separately for each password or secret. Do not leave any
`{...}` placeholder in `.env`.

The setup script renders the official Helm realm and RabbitMQ definitions for
localhost URLs, then the one-shot `register-oidc` service registers a local Core
administrator and the Keycloak provider. Check its result with:

```powershell
docker compose -f .\compose.yaml ps
docker compose -f .\compose.yaml logs register-oidc
```

`docker compose ps` reports health for the services with configured health
checks, including Core, Auth, Scheduler, Keycloak, the administrator frontend,
the policy bundle server, OPA, the gateway, PostgreSQL, and RabbitMQ. OPA's
health check uses its built-in HTTP client to query its own bundle readiness
endpoint, so no extra utilities are needed in its static image.
`admin-certificate` and `register-oidc` are one-shot jobs; inspect them with
`docker compose ps -a` and the registration logs.

Stop the services with `docker compose -f .\compose.yaml down`. To preserve
local data, do not use `down -v`. This configuration is for local development,
not production: it uses HTTP and generated development credentials.

## Read-only smoke test

From PowerShell, run:

```powershell
.\smoke-test.ps1
```

The script uses `curl.exe` to request an access token from local Keycloak and
then list Core users and roles. It reads credentials from `.env`, prints no
token or password, and does not create or modify application data.
